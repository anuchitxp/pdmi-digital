ทำให้การ update PDMI app บน Vultr/Alma9 เป็นคำสั่งเดียว โดยสร้างสคริปต์ update พร้อม safety checks

## สิ่งที่จะสร้าง/แก้

### 1. ไฟล์ใหม่: `scripts/update.sh`
สคริปต์ bash ที่รันบน server แทนการพิมพ์ 6 คำสั่งเอง มีขั้นตอนดังนี้ (เรียงตามลำดับ `set -euo pipefail` หยุดทันทีเมื่อขั้นใด fail):

1. **Pre-checks** — ตรวจว่าอยู่ใน repo (`git rev-parse`), มี `pm2` และ process `pdmi` อยู่
2. **Git status check** — ถ้า working tree สกปรก (มีไฟล์แก้ในเครื่อง server) ให้เตือนและหยุด ไม่ pull ทับ
3. **Backup DB ก่อน touch อะไร** — เรียก `scripts/backup-db.sh` ที่มีอยู่แล้ว (ใช้ default `./backups` หรือรับ path จาก env `PDMI_BACKUP_DIR`)
4. **`git pull --ff-only`** — ถ้ามี conflict จะหยุด ไม่พัง repo
5. **`npm ci`**
6. **`npm test`** — รัน Vitest ก่อน build เสมอ เพราะ goal engine เป็น clinical logic ถ้า test fail หยุด และ server ยังใช้ build เดิมได้ต่อ
7. **`npx prisma migrate deploy`** — เปลี่ยนจาก `migrate dev` ใน DEPLOY.md เพราะบน production ต้องใช้ `deploy` เท่านั้น (dev อาจสร้าง migration ใหม่/reset DB ได้)
8. **`npm run build`** — ถ้า build fail, app เดิมยังรันอยู่เพราะยังไม่ restart
9. **`pm2 restart pdmi`** — restart เฉพาะตอนทุกขั้นผ่านหมดแล้ว
10. พิมพ์ commit ก่อน/หลัง + สรุปผล

หมายเหตุ memory: เครื่อง 1 GB RAM — ในสคริปต์จะ set `NODE_OPTIONS=--max-old-space-size=768` ตอน build เพื่อลดโอกาส OOM (Next.js build บน 1 GB เสี่ยงโดน OOM killer)

### 2. แก้ `DEPLOY.md`
- เปลี่ยนหัวข้อ "Updating" จาก 6 คำสั่ง manual เป็น:
  ```bash
  cd ~/pdmi-digital
  ./scripts/update.sh
  ```
- เพิ่ม `chmod +x scripts/update.sh` ครั้งแรก
- เปลี่ยนคำสั่ง update และคำอธิบาย initial setup จาก `prisma migrate dev` เป็น `prisma migrate deploy` สำหรับบน server (ส่วน dev  local ยังใช้ `migrate dev` ตามปกติ)

## ไม่ทำ
- ไม่ทำ GitHub Actions / webhook / cron auto-pull (ตามที่เลือกไว้)
- ไม่แก้ clinical logic หรือ goal engine
